> Status: experimental. The activity format is v1 and may still change; a change bumps `schema`.

## Why

I had two tools that each wanted the notch: [Wishing-Willow](https://github.com/yha9806/wishing-willow), which shows what Claude thinks you asked next to what you said, and a writing loop that tracks a manuscript's revision round. Each drew its own island, and they fought over the same few pixels. lintel is the one program that draws. The others only write files.

## What a source does

A source program writes one JSON file per activity:

```
~/Library/Application Support/lintel/producers/<source id>/activities/<activity id>.json
```

Write to a temporary file and rename it. lintel watches the folder, validates every file against the v1 format and draws the result. A file that does not pass is rejected with its reason, and the notch shows that something was rejected. lintel does not repair it.

The format is in [`docs/protocol/activity-v1.md`](docs/protocol/activity-v1.md). That page is generated by `lintel schema` from the validation table in `Sources/LintelCore/Validation.swift`, so it cannot drift from what the host accepts. The field comments in `Sources/LintelCore/Activity.swift` say what each field means. Both documents are in Chinese for now.

What lintel draws from those files:

- the collapsed notch: a mark for the source on the left, a short label on the right;
- a hover card with the activity's sections;
- a popover when you click the notch, about the conversation the notch is showing;
- a window with a sidebar of conversations and the manuscripts nested in them.

## Build and run

Requires macOS 26 and Swift 6.2 (Xcode 26 or a matching toolchain).

```bash
git clone https://github.com/vulca-org/lintel
cd lintel
make build        # swift build -c release
make test         # optional
make autostart    # runs the host now and at every login (a LaunchAgent)
```

`make run` starts the host once in the terminal; `make autostart-off` removes the login item; `make agent-plist` prints
the LaunchAgent without installing it.

Useful commands:

| Command | What it does |
|---|---|
| `lintel paths` | prints where the registry, the activity folders and lintel's own state live |
| `lintel register <id> --name <name> [--initial X] [--event type[:attention]]` | registers a source; files from unregistered sources are rejected |
| `lintel validate [files…]` | checks activity files the way the host does; no arguments checks everything |
| `lintel schema` | prints the v1 format |

## With Wishing-Willow

Wishing-Willow's macOS app is a lintel source. With both running, a Claude Code session appears on the notch: your request and Claude's reading of it, the conversation's long list, and the turns so far. Setup steps are in the Wishing-Willow README.

## What it does not do

- It reads files; it does not talk to any network service. Nothing a source writes leaves the Mac.
- It does not sign or notarise builds. You compile it yourself.
- It has no plugin system. A new kind of content means a new field in the format.
- There is a Windows host in progress; it is not in this repository yet. `windows/fixtures/` holds the two activity files both hosts must accept.
